# 어디로 갈까? — 서비스 설계 문서

> 친구들끼리 여행지를 재밌고 신박하게 정하는 웹앱.
> SNS에서 유행한 "지도에 다트(마커펜) 던져서 여행지 정하기"에서 출발했다.

- 작성일: 2026-10-29 (최종 수정 2026-10-30)
- 상태: MVP 기능(방·기준 라운드·다트·투표·결과 카드) 구현됨. 배포 전
- 만든 이유와 결정 근거: [DECISIONS.md](DECISIONS.md)

---

## 1. 콘셉트

**"질문에 답할수록 지도가 줄어들고, 남은 땅에 다트를 던진다"**

- 재미의 핵심은 게임 장치가 아니라 **우리만의 여행 기준을 정하는 과정**이다.
- 유명한 곳만 가는 대신, 우리가 정한 조건 안에서 의외의 동네를 만나게 하는 것이 목표다.

## 2. 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 여행 범위 | 국내만 |
| 여행지 단위 | 읍·면·동 |
| 참여 방식 | 각자 폰으로 방에 참여 (실시간) |
| 로그인 | 없음. 닉네임만 입력 (기록은 그룹 링크로 보관) |
| 결정 방식 | 기준 라운드 → 한 명씩 다트 → 투표 (동점 시 룰렛) |
| 질문 형식 | 밸런스 게임 + 친구가 질문 만들기 |
| 질문 반영 방식 | 조건에 맞지 않는 지역이 지도에서 지워짐 |
| 의견 충돌 | 다수결, 동점이면 룰렛 |
| 자작 질문 처리 | AI가 데이터 기준으로 변환 |
| 데이터 기준 (MVP) | 거리/이동 시간, 여행 인프라 (+ Claude 초안: 방향·행정구역 종류·시도. 여행 인프라는 데이터 수집 전이라 아직 없음, DECISIONS 2-1장) |
| 출발지 | 방에서 하나로 정함 |
| 갈 수 없는 곳 (바다·DMZ 등) | 다시 던짐. 3번째에도 그러면 가장 가까운 육지로 이동 (기준으로 지워진 영역도 같이 처리할지는 구현 때 확인: DECISIONS P6) |
| 결과물 | 공유용 이미지 카드부터 (영상은 이후) |
| 기록 | 그룹 기록장 (지금까지 정한 여행지 누적) |

## 3. 한 판의 흐름

```
방 만들기 → 출발지 설정 → 기준 라운드 → 다트 라운드 → 최종 투표 → 결과 카드 + 기록장 저장
```

1. **방 만들기**: 방장이 방을 만들고 링크를 공유한다. 참여자는 닉네임만 입력한다.
2. **출발지 설정**: 방 단위로 하나 정한다 (예: 서울역).
3. **기준 라운드**
   - 밸런스 게임: 모두 동시에 선택하고 결과를 한꺼번에 공개한다.
   - 친구가 질문 만들기: 자유롭게 쓴 문장을 AI가 데이터 기준으로 변환한다.
   - 질문마다 다수결로 정하고, 동점이면 룰렛을 돌린다.
   - 기준이 확정될 때마다 조건에 안 맞는 읍·면·동이 지도에서 어둡게 지워지는 연출이 나온다.
4. **다트 라운드**
   - 한 명씩 차례로, 남은(밝은) 영역에 다트를 던진다.
   - 꽂힌 좌표는 읍·면·동으로 판정되어 후보에 올라간다.
   - 바다 등 갈 수 없는 곳이면 다시 던진다. 3번째 시도도 무효이면 가장 가까운 육지로 이동한다.
   - 기준으로 지워진 영역도 똑같이 처리해 가장 가까운 유효(지워지지 않은) 읍·면·동으로 옮기는 것은 Claude의 해석이라, 구현 때 확인한다 (DECISIONS P6).
5. **최종 투표**: 친구별 후보 중 투표로 결정하고, 동점이면 룰렛으로 정한다.
6. **결과**: 9:16 결과 카드 이미지를 만들고 그룹 기록장에 저장한다.

## 4. 화면 구성

| 화면 | 역할 |
|---|---|
| 홈 | 방 만들기, 링크로 참여 |
| 대기실 | 닉네임 입력, 참여자 목록, 출발지 설정 |
| 기준 라운드 | 밸런스 게임, 질문 만들기, 결과 공개, 지도가 줄어드는 연출 |
| 다트 라운드 | 지도, 차례 표시, 던지기, 꽂힘 연출 |
| 투표·결과 | 후보 비교, 투표, 룰렛, 결과 카드 |
| 그룹 기록장 | 우리가 정한 여행지를 지도에 모아 보기 |

## 5. 기준 데이터의 한계와 대응

MVP의 데이터 기준은 **거리/이동 시간**과 **여행 인프라** 두 가지뿐이다.
지도를 실제로 줄이는 질문은 이 두 기준으로만 만들 수 있고, AI 변환도 이 두 기준으로만 가능하다.
따라서 질문이 단조로워질 위험이 있다.

- **대응 1**: AI가 기준으로 바꾸지 못한 질문은 버리지 않고 **"우리 여행 규칙"**으로 결과 카드에 남긴다.
  (예: "도착하면 무조건 시장부터")
- **대응 2**: **자연·지형(바다/산/섬)** 기준을 추가한다. 질문 다양성에 가장 효과가 크다.
  지금 로드맵(9장)에서는 3단계이고, 더 앞당길지는 미정이다.
- MVP에서는 두 기준만으로도 다양한 상황을 묻는 기본 질문 목록으로 대응한다. (대응 1은 AI 변환이 들어오는 2단계부터)

## 6. 기술 구성

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | Next.js (React) + TypeScript | 웹앱 표준, 결과 카드 이미지 생성 기능 내장 |
| 지도 | MapLibre GL JS | 무료 오픈소스, 읍·면·동 경계 채색/지우기 연출이 자유로움 |
| DB·실시간 | Convex | DB와 실시간 동기화가 한 서비스에 있음. 쿼리가 구독이라 데이터가 바뀌면 모든 참여자 화면이 자동 갱신됨 |
| AI | Claude API (경량 모델) | 자작 질문 → 기준 변환. 한 판에 몇 번만 호출 |
| 배포 | Vercel | Next.js와 궁합, 무료로 시작 가능 |

> 2026-10-29: 처음에는 Supabase를 골랐으나, 무료 프로젝트 한도(2개)가 이미 차 있어서 Convex로 바꿨다. 비교와 근거는 [DECISIONS.md](DECISIONS.md) T6.

**공정성**: 다트 착지 지점은 서버(Convex mutation)에서 계산한다. 모든 참여자가 같은 결과를 보고, 조작을 막기 위함이다.

## 7. 데이터 준비 (출시 전 일회성 가공)

- **읍·면·동 경계** (완료): [vuski/admdongkor](https://github.com/vuski/admdongkor) `ver20261001`의 GeoJSON을 쓴다. (원본 커밋 `d5d5a82` 고정)
  - `npm run build:regions`가 두 파일을 만든다.
    - `public/data/boundaries.json`: 5%로 간소화한 경계 (속성은 코드만)
    - `public/data/regions.json`: 지역 목록 (이름, 시도, 시군구, 대표 좌표)
  - 대표 좌표는 원본 경계 기준으로 지역 안쪽에 반드시 들어가는 내부점(inner point)이다.
    단, 5% 간소화 경계(`boundaries.json`)에서는 11곳이 경계 밖에 놓인다 (DECISIONS T5).
  - 근거는 DECISIONS T3·T4·T5.
- **거리 기준**: 출발지에서 약 3,500개 동까지의 직선거리를 실시간으로 계산한다.
  - "편도 2시간 이내" 같은 질문은 직선거리 구간으로 근사한다.
  - 실제 길찾기 API를 통한 보정은 이후 단계에서 한다.
- **여행 인프라**: 한국관광공사 TourAPI. [공공데이터포털](https://www.data.go.kr)에서 "한국관광공사_국문 관광정보 서비스_GW"를 검색해 활용 신청하면 무료 인증키를 받을 수 있다. (정확한 페이지 주소는 확인 전)
  - 수집 스크립트로 동별 숙소·식당·관광지 개수를 미리 집계해 둔다. 실시간 호출은 하지 않는다. (저장 위치는 구현 때 결정)

## 8. 데이터 구조 (요약)

구현됨 (Convex, `convex/schema.ts`)

```
rooms        방 (코드, 진행 단계, 방장, 출발지)
players      참여자 (닉네임, 차례 순서, 토큰 해시)
presence     접속 표시 (참여자, 마지막 신호 시각) — 방 정보와 분리 (DECISIONS T10)
throws       다트 기록 (던진 사람, 시도 횟수, 착지 좌표, 결과, 대신 던졌는지)
votes        최종 투표 (결과 공개 전에는 다른 참여자에게 보내지 않음)
rounds       기준 라운드 질문 (질문, 선택지와 기준, 상태, 결과) — 낼 때의 기준을 그대로 저장
answers      질문별 응답 (공개 전에는 다른 참여자에게 보내지 않음)
```

정적 파일

```
public/data/regions.json     읍·면·동 목록 (코드, 이름, 시도, 시군구, 대표 좌표)
public/data/boundaries.json  간소화 경계 (코드)
```

예정

```
(친구 자작 질문, AI 변환 결과, 여행 규칙) — 2단계
trips        기록장 (그룹 링크 단위로 결정된 여행지 누적)
(인프라 집계) 동별 숙소·식당·관광지 개수 — DB와 정적 파일 중 어디에 둘지 미정
```

## 9. 개발 단계

| 단계 | 범위 |
|---|---|
| MVP | 방 → 밸런스 게임(거리·인프라) → 다트 → 투표 → 결과 카드 |
| 2단계 | 친구 자작 질문 + AI 변환, 그룹 기록장 |
| 3단계 | 자연·지형 기준, 결과 영상(릴스용), 실제 이동 시간 보정 |

## 10. 확인이 필요한 사항

- **Convex 무료 플랜 한도**: 공식 페이지 기준 월 함수 호출 100만 회, 프로젝트 20개(문서상 팀당 배포 40개). 저장 용량(0.5GB 등)은 외부 정리 글 수치라 [공식 가격 페이지](https://www.convex.dev/pricing)에서 재확인한다.
  접속 표시 하트비트(30초 간격)와 쿼리 재실행도 호출 수에 포함되므로, 실제 사용량을 대시보드에서 지켜본다.
- **TourAPI 사용 조건**: 호출 한도와 상업적 이용 조건은 개발 계정 신청 시 확인한다.
